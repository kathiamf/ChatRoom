# Erros e correções

Registro dos erros e inconsistências encontrados durante a implementação do
ChatRoom e das correções aplicadas.

| Etapa                     | Erro ou inconsistência                                                                                                                                                                                   | Local afetado                                                                    | Causa raiz                                                                                                                                | Correção aplicada                                                                                                                                                                                                    |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Leitura do guia           | O primeiro comando de extração terminou com `Python não foi encontrado` (código 9009).                                                                                                                   | Ambiente Windows; leitura de `ChatRoom-Guia-Passo-a-Passo.docx`                  | Python não está instalado nem disponível no `PATH`; o alias da Microsoft Store foi oferecido pelo Windows.                                | Extraí o XML do DOCX com `System.IO.Compression` e `System.Xml`, já disponíveis no PowerShell, sem instalar dependências no projeto.                                                                                 |
| Estrutura inicial         | O template Expo criou `App.tsx`, `index.ts` e configurou `main` como `index.ts`; isso não atende ao Expo Router pedido pelo guia.                                                                        | Raiz do projeto e `package.json`                                                 | O template `blank-typescript` vem configurado para a entrada React Native padrão, não para rotas baseadas em arquivos.                    | Configurei `main` como `expo-router/entry`, habilitei o plugin `expo-router` e removi os dois arquivos de entrada do template.                                                                                       |
| Arquivos omitidos no guia | A árvore do Apêndice A inclui `errors.ts` e `icons.ts`, mas não há blocos de código para eles; telas e componentes importam `friendlyError` e `IconName`.                                                | `src/utils/errors.ts`, `src/utils/icons.ts` e consumidores nas rotas/componentes | Os utilitários auxiliares foram listados na árvore, mas não foram definidos no corpo do guia.                                             | Criei `friendlyError(error: unknown)` com tipos seguros e mapeamento de falhas de rede para `Sem conexão com a internet.`; derivei `IconName` das propriedades tipadas de `Ionicons`.                                |
| Dependências              | `npm install` concluiu sem conflito `ERESOLVE`, mas o npm reportou vulnerabilidades em dependências: 3 moderadas após a instalação Expo e 1 baixa + 22 moderadas após instalar as dependências de teste. | `package-lock.json` e dependências transitivas                                   | Avisos de auditoria originados na árvore de dependências instalada, incluindo ferramentas de teste; não impediram instalação ou execução. | Mantive as versões compatíveis com o SDK 58 e não executei `npm audit fix --force`, que poderia introduzir atualizações incompatíveis. A saída de auditoria deve ser reavaliada antes de uma publicação de produção. |
| Primeira tipagem          | `TS2322` em `app/(app)/(tabs)/_layout.tsx`: `ColorValue` não era atribuível ao tipo esperado para o ícone; o segundo ajuste ainda admitia `number` na cor do ícone.                                      | Callback `tabBarIcon`                                                            | `ColorValue` também admite números e cores nativas dinâmicas, mas `Ionicons.color` aceita string ou `NativeColorValue`.                   | Mantive o tipo real do callback e passei a cor recebida somente quando é string; nos demais casos, uso `colors.muted`, aceito pelo ícone.                                                                            |
| Primeira tipagem          | `TS2769` em `app/(app)/(tabs)/index.tsx`: a função `refetch` não satisfazia o tipo `onRefresh`.                                                                                                          | `RefreshControl` da lista de salas                                               | `refetch()` devolve um `QueryObserverResult`, enquanto `RefreshControl.onRefresh` aceita somente `void` ou `Promise<void>`.               | Encapsulei a chamada com `void refetch()` para deixar explícito que o componente não depende do resultado da consulta.                                                                                               |
| Primeira execução Jest    | `Must use import to load ES Module` para `supabase/tests/db.test.mjs`; apesar disso, os 20 testes de aplicação foram encontrados e passaram.                                                             | Configuração Jest em `package.json`                                              | O padrão automático do Jest também selecionou o teste `.mjs` do PGlite, que deve ser executado pelo Node, não pelo Jest.                  | Restrinjo `testMatch` aos testes `*.test.ts` em `__tests__`; o comando `test:db` continua executando o arquivo `.mjs` via `node --test`.                                                                             |
| Expo Doctor               | `19/20 checks passed`; `expo-font` estava ausente como peer dependency obrigatório de `@expo/vector-icons`.                                                                                              | Dependências Expo no `package.json`                                              | O pacote de ícones precisa de `expo-font` instalado diretamente para evitar falhas em builds fora do Expo Go.                             | Instalei `expo-font` com `npx expo install expo-font`, selecionando a versão compatível com o SDK 58.                                                                                                                |
| Revisão do staging        | `git diff --cached --check` encontrou espaços finais em linhas vazias de `supabase/schema.sql`.                                                                                                          | `supabase/schema.sql`                                                            | A conversão de parágrafos do DOCX preservou um espaço em parágrafos usados como linhas vazias.                                            | Removi somente os espaços/tabs ao final das linhas SQL; as instruções, políticas e ordem do schema permaneceram inalteradas.                                                                                         |

As falhas de tipagem e testes, se ocorrerem durante as validações, serão
registradas aqui com a mensagem observada, a causa e a correção correspondente.
